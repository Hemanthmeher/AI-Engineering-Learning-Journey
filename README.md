## 🧠 Engineering Principles

While building, I try to keep a few principles in mind:

**01 — Understand before copying**

Code should help me understand the concept, not hide it.

**02 — Build small first**

A working small system is better than an unfinished complex one.

**03 — Experiment**

Changing one variable and observing the result is often where real understanding happens.

**04 — Document**

If I cannot explain what I built, I probably don't understand it well enough.

**05 — Think beyond the demo**

Validation, error handling, security, observability, maintainability and scalability matter.

**06 — Keep improving**

The first implementation is rarely the final implementation.

## 💾 Commit Philosophy

I don't use commits only to increase the contribution graph.

Each meaningful commit should represent a real step in the learning process.

```text
learn:   New concept understood
build:   New implementation
experiment: Testing an approach
fix:     Bug or issue resolved
refactor: Improving existing implementation
docs:    Improving documentation
```

Example:

```text
learn: understand dynamic prompt templates

build: implement basic RAG pipeline

experiment: compare chunking strategies

fix: handle empty retrieval results

docs: document retrieval workflow
```

This makes the Git history part of the learning journey.
